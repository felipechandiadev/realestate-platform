## 3. MATRIZ DE VIOLACIONES DETALLADA

### 3.1 Por Principio Arquitectónico

| Principio | Requerimiento | Estado Actual | Coherencia |
|-----------|--------------|---------------|-----------|
| **Feature-First** | Features en `features/{context}/{feature}/` | BackOffice/Portal en app/ | 0% |
| **Server Actions** | `features/{context}/{feature}/actions/{name}.action.ts` | `app/actions/{name}.ts` | 0% |
| **Hooks** | `features/{context}/{feature}/hooks/use*.ts` | Mixtura global + ? por feature | 25% |
| **Types** | `features/{context}/{feature}/types/` | Global `app/types/` | 10% |
| **Validation** | `features/{context}/{feature}/validation/` | ❌ No encontrada | 0% |
| **Services** | `features/{context}/{feature}/services/` | ❌ No encontrada | 0% |
| **Store/State** | Zustand en `features/{context}/{feature}/store/` | Context API (app/contexts/) | 15% |
| **Shared UI** | `shared/ui/` | `components/` | 50% |
| **Context Separation** | BackOffice ≠ Portal (no imports cruzados) | Ambos en app/ (riesgo alto) | 30% |
| **Naming Convention** | `{entity}.action.ts`, `use{Entity}.ts` | Inconsistente | 20% |

### 5.2 Fases de Migración

**FASE 1: Preparación (2-3 horas)**
- [ ] Crear estructura `features/` base
- [ ] Crear estructura `shared/` base
- [ ] Crear `providers/` folder
- [ ] Actualizar `tsconfig.json` con paths

**FASE 2: Refactorizar Shared (3-4 horas)**
- [ ] Mover `components/` → `shared/ui/`
- [ ] Mover `app/hooks/` → `shared/hooks/`
- [ ] Crear `shared/validation/`, `shared/types/`, `shared/utils/`
- [ ] Mover `app/contexts/` → `providers/`

**FASE 3: Migrar BackOffice (15-20 horas)**
- [ ] Crear `features/backoffice/{properties,contracts,cms,multimedia,documents,users,notifications}/`
- [ ] Mover actions: `app/actions/{properties,contracts,documents,multimedia,notifications,users,*}.ts` → `features/backoffice/{feature}/actions/`
- [ ] Renombrar a `.action.ts` convention
- [ ] Crear services layer
- [ ] Crear hooks por feature
- [ ] Crear stores (Zustand)
- [ ] Mover/refactorizar componentes de `app/backOffice/{feature}/` → `features/backoffice/{feature}/components/`
- [ ] Actualizar imports en pages
- [ ] Crear `index.tsx` exports

**FASE 4: Migrar Portal (10-15 horas)**
- [ ] Crear `features/portal/{properties,blog,rentProperties,saleProperties,myContracts,myProperties,favorites,testimonials,contact}/`
- [ ] Mover actions correspondientes
- [ ] Crear hooks, services, stores
- [ ] Refactorizar componentes
- [ ] Actualizar imports

**FASE 5: Shared Features (5-10 horas)**
- [ ] Crear `features/shared/{auth,locations,common}/`
- [ ] Mover acciones compartidas
- [ ] Organizar validations centrales

**FASE 6: Testing & Validation (5-10 horas)**
- [ ] Validar imports cruzados
- [ ] E2E tests
- [ ] Build check
- [ ] Documentar public APIs de cada feature
